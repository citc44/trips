# Story 4.2: Action Drawer & Breadcrumb Navigation

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an Organizer,
I want to reach End Voyage, Grant Organizer Status, and Remove Voyager from a breadcrumb icon that opens a drawer,
so that organizer actions are consolidated behind clear, discoverable chrome instead of a floating bottom sheet.

## Acceptance Criteria

1. **Given** Story 4.1's `action-drawer` spec (DESIGN.md), **when** I tap the hamburger icon in Live Map's top chrome, **then** the action drawer slides in from the right **over** the still-visible map (not a full-screen takeover), showing End Voyage and Remove Voyager (Organizer-only rows) plus Grant Organizer per-member.
2. **And** selecting a row swaps the drawer's own content into a confirm step (End Voyage confirm, or Remove-this-Voyager confirm) — the confirm UI renders inside the same drawer panel, never a second stacked dialog and never a separate full-screen replacing the map.
3. **And** the drawer closes (slides back out, scrim fades out) after an action completes, or on explicit dismiss (close button or scrim tap) — it is not a persistent nav surface.
4. **And** the old full-screen organizer-menu / End-Voyage-confirm / Remove-Voyager-confirm views are removed from `active-voyage.tsx` entirely, fully replaced by the drawer.
5. **And** the drawer's open/close animation matches `EXPERIENCE.md`'s Motion & Transitions spec exactly: `280ms`, `cubic-bezier(.22,.85,.35,1)`, panel `translateX(100%) → translateX(0)`, scrim (`#1D2A44`, solid) opacity `0 → 1` simultaneously; both disabled (instant show/hide, no animation) when Reduce Motion is on.
6. **And** the built drawer matches `mockups/key-live-map.html`'s "Action Drawer Open" frame exactly: `270px` width, white (`#FFFFFF`) panel, row colors/radii as specified — not an approximation.

*(Fulfills EXPERIENCE.md line-53 IA amendment; replaces UX-DR14 / `organizer-sheet`.)*

## Scope decision (read this before writing any code)

**This story does NOT re-skin the rest of Live Map.** Story 4.3 ("Live Map Redesign") owns turning `hud-top`/`hud-bottom` into the new solid-blue `map-banner`/`hud-bar`, re-skinning `map-marker`/`status-pill` colors, and switching the Mapbox style off `Mapbox.StyleURL.Dark`. This story touches **only**: the hamburger trigger button itself (new, final Wayfinder look — nothing old to preserve), and the new `ActionDrawer` component (new, final Wayfinder look). Everything else on the screen — the still-dark `hud-top` card the hamburger sits inside, the dark map style, the old-palette markers/status-pill — is **left exactly as-is**. The screen will look visually mixed (a white/blue hamburger+drawer over an otherwise still-dark Night Drive screen) until 4.3 lands. This is intentional, not a gap to fix here — do not re-skin `hud-top`, `hud-bottom`, `MapMarker`, or `StatusPill` in this story.

**The confirm steps move inside the drawer, not just the row list.** The current implementation (`removeTarget`/`showConfirm` state) renders End Voyage confirm and Remove Voyager confirm as **separate full-screen views** that replace the entire map (see `active-voyage.tsx` lines 584–641 on the baseline commit). AC #2's "swaps the drawer's own content into a confirm step" is a real structural change from that: the confirm UI must render *inside* the same 270px drawer panel, with the map still mounted (just covered by the drawer+scrim), not as a `screenStyles.container`-styled full-screen swap. `screenStyles`/`IgnitionButton` are both still Night-Drive-styled (dark background, gradient pill) — do not reuse them inside the new white drawer; they'd look broken against a white panel. Build plain `Pressable`/`Text` rows for the drawer's own primary/secondary/destructive actions, styled from the new `ActionDrawer` design token (see Task 6) — mirroring how the drawer's row list itself is already specified, not `IgnitionButton`.

**The map must stay mounted while the drawer is open.** Today, `showOrganizerMenu`/`showConfirm`/`removeTarget` are early-return branches — when any is true, `MapView` (`testID="live-map"`) unmounts entirely. For the drawer to slide in as an animated overlay, the map/HUD must stay mounted underneath it at all times; the drawer is a new absolutely-positioned layer, not a routing switch. (Visually the end state looks similar to today once the drawer is fully open — the scrim is fully solid, not translucent — but the map is still there, just covered, and the drawer can now animate.)

**Code review patch pass (2026-08-03):** all 12 patch findings plus the one decision-needed finding (motion-timing split, resolved per user decision toward `motion-demo.html`'s decoupled timing) fixed — see Review Findings above for the full list. Two notable structural fixes beyond the findings' own descriptions:
- `accessibilityViewIsModal` had to move from the panel alone onto a new wrapper `View` (`testID="action-drawer-root"`) around *both* the scrim and the panel — VoiceOver (and `react-native-testing-library`'s own accessibility-aware queries, which model the same rule) treat every host *sibling* of an `accessibilityViewIsModal` element as hidden from assistive tech, which was making the scrim itself unreachable when the prop sat on the panel alone. It's also now gated on `visible` directly (not the animation's own progress), matching the scrim's `pointerEvents` gating, so sibling content like the outbox toast doesn't stay hidden through the close animation.
- The `outbox-toast` needed to stop being a direct sibling of that same `accessibilityViewIsModal` node for the same reason (it must stay reachable/audible while the drawer is open, e.g. confirming a Grant Organizer action taken from inside it) — `active-voyage.tsx` now groups the map/HUD and the drawer together under one wrapper (`mainContentGroup`), with the toast rendered outside that group entirely.
- `EXPERIENCE.md`'s Motion & Transitions section updated to describe the panel/scrim's independent timing (280ms/bezier vs 260ms/ease) instead of the earlier "same duration" prose.
