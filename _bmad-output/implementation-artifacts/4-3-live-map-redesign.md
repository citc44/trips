# Story 4.3: Live Map Redesign

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Voyager,
I want the Live Map to open with a clear destination banner and a clean, colorful map view of everyone in the group,
so that the core screen reads as an inviting game-like world instead of a dark, hard-to-parse HUD.

## Acceptance Criteria

1. **Given** Story 4.1's respecced Live Map layout (DESIGN.md `map-banner`), **when** I open Live Map, **then** a solid, non-floating `accent-primary` banner is docked to the top of the screen, always showing the Voyage destination — not a floating glass card over the map.
2. **And** the full map renders below the banner (not full-bleed-with-overlaid-cards), with each Voyager shown via the re-specced `map-marker` (circular avatar, player-color ring, heading chevron, name tag) and the re-specced `status-pill` (Riding: white/hairline; Driving: solid teal, no glow).
3. **And** no glass, blur, or transparency is used anywhere on this screen — every surface (banner, HUD, any overlay card/scrim) is a solid, opaque fill.
4. **And** all existing Live Map *behavior* is preserved unchanged: realtime location updates, recenter control, connectivity-loss handling (reconnecting note, last-known positions), role switch (status pill tap), marker tap → peek card, Organizer menu → Action Drawer (Story 4.2, untouched by this story). Exception, per explicit scope decision below: the always-visible per-Voyager roster/distance panel in the old floating bottom HUD is intentionally dropped, not relocated — see Scope decision.
5. **And** entering Live Map from Destination Picker (Organizer, via the Join-code screen's Continue) or from Join + OTP completion (Voyager, via `voyage-joined.tsx`'s Continue) uses `EXPERIENCE.md`'s "cut to gameplay" transition (solid-blue flash-and-pulse, then Live Map pops to rest) — not a default screen push, and not shown on cold app relaunch mid-Voyage (which must still land directly on Live Map, no flash).
6. **And** the built screen matches `mockups/key-live-map.html`'s base (non-drawer) frame exactly — colors, spacing, radii, component treatment — verified side-by-side during code review, not approved on "close enough."

*(Fulfills Story 4.1's Live Map respec; supersedes visual portions of Stories 3.2, 3.4, 3.5 — no behavioral change to those stories except the one explicit roster-panel removal above.)*

## Scope decision (read this before writing any code)

**The always-visible bottom-HUD roster panel is removed, not relocated — a deliberate product call, not an oversight.** Today's `hud-bottom` (`active-voyage.tsx` ~L806-825) renders a per-member list (name, role, live distance from destination) at all times. `mockups/key-live-map.html`'s bottom `.hud` shows only an "Elapsed" stat-chip and the recenter button — no roster at all. **Confirmed with the user: match the mockup exactly.** The roster data isn't orphaned — names+roles are still reachable via the Action Drawer's existing `drawer-member-list` (Story 4.2, unconditional for all viewers, not Organizer-gated), and any individual Voyager's live distance is still reachable by tapping their map marker (`marker-peek-card`, already shows `getDistanceLabel`). What's lost is only the always-visible, no-tap "everyone's distance at a glance" view — accepted tradeoff, not a bug. Delete `hud-bottom`'s roster JSX/styles and the tests that assert its roster rows (see Testing below); do **not** try to preserve or relocate that data anywhere new.

**Elapsed time moves from the top banner to the bottom HUD.** Today `hudElapsed` renders inside `hud-top`. The mockup's top `.banner` has no elapsed-time text at all — elapsed lives in the bottom `.hud`'s `.stat-chip` ("Elapsed" / "2h 14m"). Move `formatElapsed(...)`'s render site accordingly; the `now`-ticking `setInterval` effect and its `showOrganizerMenu` gate are unchanged.

**The Mapbox map style switches from Dark to Street.** `MAP_STYLE_URL` (L57) currently resolves to `Mapbox.StyleURL.Dark` (native) / `'mapbox://styles/mapbox/dark-v11'` (web). DESIGN.md's `map-*` tokens describe a literal stylized-flat-terrain look that would require a custom Mapbox Studio style asset — not available in this repo, out of reach for this story. The pragmatic, honest fix: switch to `Mapbox.StyleURL.Street` (native) / an equivalent light street style (web) — the closest built-in approximation, not a pixel-match of the mockup's flat CSS terrain. `Mapbox.StyleURL.Street` is confirmed to exist on both native and the web shim (see the existing comment at L50-56 in `active-voyage.tsx`, which already documents the web shim's available styles). Flag the terrain-color gap as an `[ASSUMPTION]` in Dev Notes, don't silently claim full mockup terrain fidelity.

**A real navigation gap must be fixed for AC #5 to be satisfiable.** Traced both entry paths into Live Map:
- **Join + OTP (Voyager) — already correct.** `voyage-joined.tsx` is itself `Stack.Protected`-guarded on `hasPendingJoin` (`_layout.tsx` L122-124). Its `handleContinue()` (L76-82) clears `pendingJoinCode`, which flips that guard false; Expo Router's `Stack.Protected` then evicts this screen and redirects to the next matching guard — `hasActiveVoyage` is already true (refetched at L63 before Continue is even tappable), so it lands correctly on `active-voyage.tsx`. This path needs no navigation fix, only the transition wired in at the point Live Map first renders after this landing.
- **Destination Picker (Organizer) — broken today, must be fixed.** `destination-picker.tsx`'s `handleStartVoyage()` refetches `activeVoyage` then does `router.push('/join-code', ...)` (L85-101). `join-code.tsx`'s "Continue" button does `router.back()` (L86) — but neither `destination-picker.tsx` nor `join-code.tsx` is `Stack.Protected`-wrapped, so there's no automatic eviction/redirect the way `voyage-joined.tsx` gets. `router.back()` lands back on the still-mounted `destination-picker.tsx` screen instance, **not** on Live Map. This is a real, pre-existing gap (not introduced by this story, but this story's AC #5 can't be satisfied without fixing it). Recommended fix, mirroring `voyage-joined.tsx`'s own working pattern: wrap `join-code.tsx` in a `Stack.Protected` guard too (e.g. gated on a transient "just started a Voyage, haven't confirmed the join-code screen yet" flag, cleared by Continue) so the same eviction-redirect mechanism applies. The exact flag/mechanism is an implementation call — see Dev Notes' suggested approach — but the end state must be: tapping Continue on `join-code.tsx` lands on `active-voyage.tsx`, not back on `destination-picker.tsx`.

**No mockup exists for `marker-peek-card` or `role-prompt`.** Neither appears in any Wayfinder mockup or `EXPERIENCE.md` visual spec. AC #6's mockup-exact mandate doesn't literally apply to them (there's nothing to match), but AC #3 ("no transparency anywhere") does — today's `peekScrim` uses `${Colors.surfaceMidnight}8C` (a translucent dark overlay), a direct violation. Re-skin both by analogy to the Action Drawer's own established solid-scrim pattern (Story 4.2): a solid navy scrim (reuse `#1D2A44`, same as `action-drawer`'s scrim), and the card itself using DESIGN.md's `card` token (`surface-primary` white, `border-hairline`, flat `0 2px 0 border-hairline` shadow) instead of the old `HudCard` glass token.

## Dev Notes

- **Previous story's regression class to watch for:** Story 4.2's code review found (and this session's patch pass fixed) a subtle bug where `accessibilityViewIsModal` on one element hides all of its *host siblings* from both real screen readers and `react-native-testing-library`'s own accessibility-aware queries. This story doesn't add a new `accessibilityViewIsModal`, but if any new overlay/transition component in Task 8 uses similar modal-style accessibility props, apply the same lesson: scope it to a wrapper around everything that must stay reachable together, and test with `getByTestId`/`getByText` (not just visual review) to catch silent hiding.
- **Motion pattern precedent:** this codebase's only existing `Animated` usage (`VoyagerMarker`'s pulse, `action-drawer.tsx`'s slide/fade) uses RN's built-in `Animated` API, not `react-native-reanimated` — follow the same precedent for Task 8's transition, don't introduce a new animation library.
- **`react-hooks/set-state-in-effect` workaround:** if Task 8's transition needs to defer a `setState` inside an effect (e.g. clearing the transient "just arrived" flag after the flash), use the established `Promise.resolve().then(() => setState(...))` microtask pattern already used in `use-live-locations.tsx` and `action-drawer.tsx`.
- **Test count baseline:** `active-voyage.test.tsx` currently has 64 passing tests. Several will need updating/removing per Task 3 (roster-row tests) — see Testing below. Don't let the total shrink without accounting for every removed test in Completion Notes.
- **`[ASSUMPTION]`:** the Mapbox terrain re-skin (Task 4) is a best-available-built-in-style approximation, not a literal match of the mockup's flat-toned CSS terrain — a true match would need a custom Mapbox Studio style asset outside this repo's reach. Flag this plainly in Completion Notes rather than silently claiming full AC #6 fidelity for the map background specifically (marker/banner/HUD fidelity is still fully achievable and required).
- **`[ASSUMPTION]`:** the mockup's marker avatar measures 44px while `DESIGN.md`'s `map-marker.size` token says 40px — a real, small mockup/token discrepancy. Per the fidelity mandate ("where this document and a mockup ever disagree on *how it looks*, that's a bug to resolve, not a case where this document silently wins" — `EXPERIENCE.md` L58), treat the mockup's 44px as authoritative and flag the token as needing a follow-up correction, the same class of fix Story 4.2's code review made to `ActionDrawer`'s row tokens.
