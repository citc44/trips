- (decision) Why: pain (no shared record of a group road trip) + opportunity (market research: growing behavior, unclaimed white space between Life360's trust-liability utility framing and Convoy Tracker's non-fun-first functional framing) + vision (live presence as a game, ending in shareable Memory Lane)
- (capability) CAP-1 (v1): Email OTP sign-in, no password. intent: user authenticates via one-time emailed code. success: valid code signs in; invalid/expired code shows error+resend.
- (capability) CAP-2 (v1): Persistent session. intent: authenticated user stays signed in until explicit sign-out. success: no re-auth prompt on relaunch; sign-out invalidates session on that device (and, per AD-4, globally).
- (capability) CAP-3 (v1): Start Voyage. intent: an Organizer starts a new Voyage with a single destination. success: creates Voyage with creator as first Organizer/Voyager, live tracking active; no second destination addable (v1).
- (capability) CAP-4 (v1): Generate Join Code/Link. intent: an Organizer obtains a shareable Join Code/Link. success: available immediately on Voyage start, shareable via OS share sheet, valid for the Voyage's full duration.
- (capability) CAP-5 (v1): Join Voyage via Code/Link. intent: any user joins an active Voyage via a valid Join Code/Link, no approval required. success: invitation screen shown pre-auth; completing OTP adds user as Voyager, immediately visible on live map; late join yields a 'fashionably late' Fun Fact, not an error.
- (capability) CAP-6 (v1): End Voyage. intent: an Organizer manually ends an active Voyage. success: ending stops new recording immediately but lets in-flight captures finish; never auto-triggered on arrival; v1 build surfaces a calm 'Voyage Ended' summary as the terminal state (superseded by Memory Lane in v1.1).
- (capability) CAP-7 (v1): Grant Organizer Status. intent: an Organizer grants Organizer status to another Voyager. success: newly granted Voyager gains End Voyage/Remove Voyager/Grant Organizer Status capabilities; a Voyage can have more than one Organizer.
- (capability) CAP-8 (v1): Remove Voyager. intent: an Organizer removes a Voyager from an active Voyage. success: removed Voyager's location/further Fun Fact capture stop being visible/possible immediately; primary mitigation for a leaked Join Code/Link.
- (capability) CAP-9 (v1): Real-time Voyager map. intent: any Voyager sees all Voyagers' live locations on one shared, game-like map for the active Voyage. success: near-real-time position updates; not a standard turn-by-turn view; visibility scoped to that Voyage's own Voyagers only.
- (capability) CAP-10 (v1.1): Manual Fun Fact logging. intent: any Voyager logs a spotting (police/deer/construction/etc.) with one tap. success: one-way lighthearted group notification; accumulates toward a Fun Fact attributed to that Voyager; no reply capability.
- (capability) CAP-11 (v1.1): Automatic event detection. intent: system auto-detects and logs long stops and border crossings, no Voyager action required. success: long stops trigger a one-way group notification; border crossings are time-stamped and silently banked; no missed-exit detection attempted.
- (capability) CAP-12 (v1.1): In-app photo logging. intent: any Voyager attaches a photo to a moment during the Voyage. success: photos stored per Voyage and Voyager, become Memory Lane source material.
- (capability) CAP-13 (v1.1): One-time contextual nudges. intent: first-time Voyagers get one-time contextual nudges introducing Fun Fact logging and photo capture, at the moment each becomes relevant. success: each distinct nudge fires at most once per Voyager, ever; no persistent tutorial.
- (capability) CAP-14 (v1.1): Generate Memory Lane. intent: system generates a Memory Lane highlight-reel when a Voyage ends. success: includes accumulated Fun Facts, photos, in-drive moments; triggers on End Voyage; a solo Voyage still produces a complete Memory Lane.
- (capability) CAP-15 (v1.1): View Memory Lane together. intent: all Voyagers on a completed Voyage can view and revisit its Memory Lane. success: every participating Voyager opens it from their own app, any time after the Voyage ends, not just once.
- (capability) CAP-16 (v1.1): Share Memory Lane externally. intent: any Voyager shares their Voyage's Memory Lane to external platforms. success: produces a self-contained artifact viewable without the Voylo app; content featuring another Voyager requires that Voyager's consent (per-share 'Ask the group' approval, resolved in EXPERIENCE.md) before external sharing.
- (constraint) Voyage data (location, Fun Facts, photos) is scoped to that Voyage's own Voyagers only; never sold or shared with third parties.
- (constraint) No in-app messaging or reply capability anywhere; every notification is one-way, system-to-group.
- (constraint) The police Fun Fact is retrospective/lighthearted only, never a live warning system - explicit boundary given jurisdictional legal risk.
- (constraint) Manual Fun Fact logging and photo capture are for passengers only; driver enforcement is consent-based (self-declared role + one-time Driver Attention Consent acknowledgment), not sensor/technical detection - a deliberate, disclosed tradeoff.
- (constraint) Single destination per Voyage in v1; no multi-leg itinerary planning.
- (constraint) Holding a valid Join Code/Link is sufficient to join - no Organizer approval/gatekeeping step.
- (constraint) A Voyager belongs to at most one active Voyage at a time, enforced at the database level (AD-9).
- (constraint) Battery impact of continuous location tracking must be actively budgeted/load-tested - the category's most-cited failure mode (Life360).
- (constraint) Core Voyage lifecycle must degrade gracefully through cellular dead zones - a connectivity drop must not silently lose a Voyager or corrupt Voyage state.
- (direction) Non-goals: no in-app messaging/chat; no real-time missed-exit/route-deviation alerting; no real-time law-enforcement-evasion tooling; no commercial/logistics fleet/dispatch functionality; no Organizer approval/gatekeeping on joins; no solo (non-group) drivers as a use case; no payments/monetization infrastructure in v1/v1.1; no phone-number OTP in v1 (email only for now); no web companion in v1/v1.1.
- (decision) Success signal: a group starts a Voyage, invites others via a link, sees everyone live on the map for the whole drive, and ends it cleanly with a calm summary - demonstrable end to end without Fun Facts or Memory Lane existing yet - and at least one Organizer starts a second Voyage within 90 days (SM-3), showing the bare v1 loop has standalone value before v1.1 investment. Full metrics dashboard (SM-1 to SM-4, counter-metrics) in companion success-metrics.md.
- (assumption) Monetization: fully free for v1/v1.1, no billing infrastructure - not explicitly confirmed by the user; revisit once the core loop and Memory Lane are proven.
- (question) Exact GPS/location refresh interval for the live map (CAP-9) - battery vs. live-feel tradeoff, needs engineering input.
- (question) Exact stop-duration threshold for automatic long-stop detection (CAP-11).
- (question) OTP delivery SLA - no concrete target set anywhere yet.
- (question) Share-asset generation performance target for Memory Lane (CAP-16).
- (question) Where the Groq-powered AI content-generation agent (provider confirmed in ARCHITECTURE-SPINE.md) fits on the roadmap relative to v1.1 Memory Lane - timing/sequencing, not provider choice, is what's open.
- (question) Legal review of the police Fun Fact across target jurisdictions - recommended before wide release.
- (question) Market sizing for Voylo's exact category is unproven (third-party estimates disagreed by an order of magnitude). A cheap demand-validation step (e.g. landing-page/waitlist test) was recommended, not yet acted on.
- (question) Indefinitely-running Voyages (an Organizer who never taps End Voyage) are an accepted v1 risk, not solved upfront - revisit if real-world usage shows a problem (battery complaints, zombie Voyages).
