- (decision) Stakes: launch-tier (starts with limited hobby-scale users, but built as if publicly available to anyone)
- (decision) Working mode: Coaching path, Journey-led entry point
- (decision) Primary inputs: brainstorming session memlog/keepsake (brainstorm-group-road-trip-tracker-2026-07-21) and market research doc (market-group-road-trip-coordination-and-travel-social-app-market-voylo-research-2026-07-24); no additional inputs volunteered
- (decision) Platform: iOS/Android native app for v1; web companion (for viewing shared recap without the app) planned later, not in this PRD's scope
- (decision) Auth: passwordless OTP via email for v1 (later phone-number OTP); session persists until explicit sign-out; same flow for organizer and joiners
- (decision) Solo-organizer value: even if nobody else joins, the organizer still gets full stats/recap from their own drive - this becomes the artifact that entices others to join next time
- (decision) Mid-journey joins are supported; a family joining late is captured as a lighthearted, non-offensive 'fun stat' (e.g. late arrival) in the recap, not treated as an error state
- (idea by user) Border-crossing detection: app records the moment/time each family crosses a state or country border and turns it into a fun-fact/memory-lane card; comparing crossing times across multiple cars is part of the appeal
- (decision) Dropped 'missed exit' alarm from scope: unreliable/noisy signal because group members often intentionally take different GPS routes, not actually missing the exit - not worth building for now
- (decision) No in-app messaging feature for v1: long-stop detection surfaces a lighthearted, one-way humorous notification to the rest of the group, not a prompt for others to reply/send messages
- (decision) North-star product goal: the emotional payoff must be strong enough that experiencing one trip makes people want to create more road-trip memories with Voylo - this must permeate every sensory layer (visual, sound, layout, copy), critical brief for UX/UI design, not just a feature checklist item
- (decision) Glossary naming confirmed: trip session = 'Voyage' (not Journey/Convoy - Convoy avoided as it's a competitor app name), participant/family unit = 'Voyager' (user's own suggestion), end-of-trip highlight = 'Memory Lane' (term user used organically twice during brainstorming), stat callouts = 'Fun Facts'
- (decision) Fun Fact logging is hybrid: police/deer/construction (and similar spot-able events) are manually tap-logged by any Voyager; other events (rest area stops, gas stops, border crossings) are auto-detected by the app wherever technically possible
- (decision) First-time-user discoverability is a named problem: since Voylo isn't GPS navigation (where the value is self-evident), new users need gentle, non-intrusive contextual nudges after starting a Voyage to learn they can tap-log spottings, take photos, and check live stats - must be informative without being noisy/annoying
- (decision) Resolved: (1) single destination per Voyage for v1, no multi-stop itineraries; (2) holding a valid Join Code/Link is sufficient to join, no Organizer approval step; (3) Voyage ends only via manual 'End Voyage' tap by the Organizer, not auto-detected arrival - reasoning: Voyagers arrive at different times, so auto-ending on first arrival would cut off Fun Facts/stats for Voyagers still en route
- (decision) MVP Scope confirmed: v1 launch = Auth (4.1) + Voyage Setup & Invite (4.2, incl. End Voyage) + Live Map & Presence (4.3) only. Fun Fact Capture (4.4), Onboarding Nudges (4.5), and Memory Lane (4.6) deferred to v1.1 fast-follow
- (decision) Aesthetic/tone direction: game-like, glamorous, clean, intuitive, 'sexy', incredibly appealing - Voyagers should feel part of the game, and feel FOMO if they don't contribute to Memory Lane. This is the concrete design brief for the emotional north-star JTBD

- (decision) Persona scope resolved: family and friend-group Voyagers are both valid v1 targets, not sequential segments - the core appeal (collected memories, game-like visual) is persona-agnostic, not specific to a gamification-seeking youth segment. Chintan (family) is a representative persona, not an exclusion of friend-groups

- (decision) Resolved orphaned-Voyage risk: Organizer can grant co-organizer status to another Voyager, so an unreachable original Organizer isn't a single point of failure for ending the Voyage
- (decision) Declined auto-end safeguard for indefinitely-running Voyages: accepted as a v1 risk to observe in real-world usage rather than solving upfront
- (decision) Resolved leaked-Join-Code risk: Organizer (or co-organizer) can remove any Voyager found not to be part of the group, rather than revoking the code itself
- (decision) Resolved external-sharing consent gap: content featuring other Voyagers (e.g. photos with them visible) requires their consent before being shared externally from Memory Lane - not automatically shareable by any single Voyager
- (decision) Resolved End Voyage race condition: End Voyage is a checkpoint that stops new recording from that point forward, but does not interrupt or discard captures/uploads already in progress - those complete normally and are included in Memory Lane
